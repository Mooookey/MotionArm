# 下午手腕端开发交接

> 历史交接资料：旧按住A、mode及速度积分不作为当前依据。现行腕端保留USB att:3并发送ESP-NOW v2，robot仅无动力联调，A点击跟随/B点击夹爪，统一5000ms保护。请以[无动力执行端](17_No_Power_Executor.md)为准。

基线：2026-11-18。[当前机械臂参数与3D零点](Robot_Baseline.md)、[结构化基线](../config/robot_baseline.json)、[最新串口演示](archive/Wide_Slow_Demo_V2.md)。本次交接整理不代表下午功能已开发或实机联调完成。

## 当前程序分别能做什么

| 入口 | 已有功能 | 尚未完成／区别 |
| --- | --- | --- |
| `firmware/joint_demo_v2` | COM7、115200、文本命令，当前取放姿态与高位旋转 | **没有ESP-NOW接收**，不能直接接收腕端或后端NDJSON控制 |
| `firmware/wearable` | MPU姿态估计、按钮、ESP-NOW发送、USB诊断JSON | 佩戴轴向、扰动恢复及模式切换需复测 |
| `firmware/robot` | ESP-NOW接收、速度积分、USB NDJSON、控制权和限幅框架 | `ArmProfile.h`仍为空，动作锁定；未合入最新演示 |
| FastAPI／Vue | 控制台、串口桥、录制回放框架 | 后端只支持mock或robot串口源，尚无COM8独立只读模式；尚无Three.js／Remotion 3D |

同一块ESP32一次只运行一套固件。下午先决定在正式 `robot` 中接入当前标定与演示能力，不能同时烧两套固件或声称当前演示已无线联调。Vue仍是现有工程，3D后续使用同一份竖直零点与尺寸基线。

## 硬件与端口

- 最近执行端COM7、腕端COM8，插拔后确认端口和role，端口号不是板卡身份。两端USB诊断115200。Arduino串口监视器、脚本和后端不可同时独占同一个COM口。
- MPU6050：VCC→3V3、GND共地、SDA21、SCL22，地址/WHO_AM_I为0x68；启动静置250样本，100Hz采样约2.5秒完成零点估计。
- A接GPIO25，按住使能；B接GPIO26，短按完成触发夹爪事件、长按≥700ms切换mode。两按钮低电平触发，软件消抖30ms。mode=0大臂、mode=1小臂。
- 执行端PCA9685地址0x40，SDA21、SCL22；逻辑3.3V，舵机独立5V并共地。CH14底座、CH15大臂、CH13小臂、CH12夹爪。
- 当前代码保存的STA MAC：腕端 `EC:E3:34:EF:81:64`，机械臂 `C0:CD:D6:D0:9B:54`；来自以前本机读取，换板或烧录后再核对启动打印，维护 `MotionArmPeers.h`。

## 无线接口：沿用现有代码

唯一编码实现为 `libraries/MotionArmLink/src/MotionArmLink.h`。WiFi STA、ESP-NOW固定信道6、单peer、25Hz发送。无需路由器，不把校园Wi-Fi连接混入控制信道。接收回调只验证并放入最新帧，不在回调操作I²C。

| 偏移 | 字段 | 类型与单位 |
| --- | --- | --- |
| 0/1 | version / msg_type | 各uint8，均1 |
| 2 | flags | uint16；bit0 IMU有效，bit1 A/deadman，bit2已校零 |
| 4/8/12 | boot / seq / uptime | 各uint32；boot非0、seq递增、uptime毫秒 |
| 16/18 | roll / pitch | 各int16，0.01度，已扣腕端中立偏置 |
| 20 | mode | uint8，0大臂／1小臂 |
| 21 | gripperEvent | uint8模256事件计数，不能按电平逐包开合 |
| 22 | CRC16 | uint16，CCITT-FALSE，覆盖前22字节 |

总长24字节、固定小端；使用encode/decode，不裸发C结构体。CRC参数poly=0x1021、init=0xFFFF、xorout=0。拒绝错MAC、版本、长度、CRC、重复和倒序包。以执行端最后接纳帧的本地时间判断250ms超时，不能直接相减两块板的uptime当单程延迟。MAC层发送成功不是舵机动作确认。

## 从手腕角到关节命令

沿用**速度控制**：Roll控制底座，Pitch控制当前mode选中的臂；回正、松开A、无效姿态或失联时停止推进，承重轴仍可能保持力矩。仅在WEARABLE拥有控制权、有效校准且完成重新使能条件时积分。释放A并回中立至少100ms，再重新按下，防止带旧姿态直接恢复运动。

1. 接收的roll/pitch除100成为度。腕端已减去开机中立值，执行端不能再扣一次。装配零点1610/1630/1570、腕端中立零点、当前45°待机位是三件事。
2. `w=clamp((abs(angle)-5)/(30-5),0,1)`；`v=sign(angle)×axis_sign×vmax×w`。死区5°、最大有效倾斜30°；axis_sign按实际佩戴选±1，当前尚未确认。vmax和加速度必须由下午实测配置，本交接不把试验时间反推成安全速度上限。
3. 正式robot以20ms周期积分并限加速度、关节范围和组合工作区。底座正角约定为俯视逆时针；大臂和小臂正角采用从竖直参考向下的α、β。再按基线中的分段/线性关系转名义µs，不把手腕角直接发给PCA9685。
4. 例如大臂α=45°→1030µs，α=60°→约830µs；小臂β=45°→1050µs，β=60°→约877µs。3D显示用θ=90°−α、φ=−β；底座ψ直接使用偏航角。夹爪是独立开合量，不虚构第四个空间转轴。
5. 正式profile的home是分段映射锚点，同时用于启动。直接把旧竖直home_us改成45°待机脉宽会改变映射含义；接入时应将映射锚点与启动姿态分开，或以已知取样点构造等价单调映射并测试。当前整理不会自动修改或生成可动profile。

B短按事件只在A有效且接管条件满足时执行一次，切mode不应把上一轴目标清零或跳到手腕绝对角。失效期间发生的事件不积压，恢复后不补执行。

## 必须处理的集成差异

- 当前演示允许最多3秒夹持，计划2.6秒；正式 `generate_profile.py` 明确只接受≤700ms，旧无线执行路径也按profile限时。本次保留限制，不能直接把3000填进去后宣称可用。后续如需无线触发整段演示，应明确独立的演示控制权、超时和STOP行为，并完成实物验收。
- 最新演示不是位置闭环；`q_out`只能称软件目标。无线radio状态、tx_ok、ACK都不证明实际到位。无外部编码器，3D只能跟随软件目标或腕端预览。
- 配置中的动作锁定继续保留。串口演示、PC手动、回放与腕端不能同时控制输出，需先停当前owner再转交；松开A不等于关闭承重轴PWM。
- 现有后端默认配置路径不是 `robot_calibration.local.json`，接入时显式设置 `MOTIONARM_CALIBRATION`，参见 [本机启动](Local_Quickstart.md)。

## 下午推荐验收顺序

1. 动力关闭，腕端启动静置、检查valid，分别绕两个轴倾斜，记录轴符号和零点；验证A、B短按、B长按。旧轴向经验只能参考，不替代绑手后的确认。
2. 动力关闭，在正式robot锁定固件验证信道、MAC、24字节帧、序号和失联状态。换入robot会替换当前串口演示，切换前保留源码与参数。
3. 前端先只读显示Roll/Pitch/mode/有效性；如需Arduino独占COM7时仍看手腕，单独实现COM8只读源，不能假设现有后端已经支持。
4. 用同一竖直基线制作3D模型，先验证45°待机和低位姿态转换，再接软件目标。没有实物闭环的地方标注估算预览。
5. 完成映射锚点、启动姿态、边界、速度、组合工作区和夹爪策略配置后，再启用受控实机小范围试验，验证松A、失联、重启、STOP与控制权冲突。

交接不包含传感器轴符号或安全速度的虚假实测值；留空项是待现场确定，不应凭演示能运动就全部置为verified。
