# 真实 IMU 与虚拟机械臂控制台

本阶段链路为 MPU6050 → 腕端 ESP32 → USB → FastAPI → 虚拟执行端 → Vue/Three.js。实体执行端、ESP-NOW、PCA9685 和舵机不接入。所有模型姿态均为 **虚拟关节目标／估算预览**，没有关节实测反馈。

## 安装与启动

请使用 Python 3.10 或以上。本机 `python` 默认指向旧 Anaconda 3.7，应使用 `py -3.13`。


打开 <http://127.0.0.1:5173>。后端默认 `wearable`；保留 `mock`、`serial` 供旧接口使用，新界面不提供模拟输入或实体控制入口。仅绑定本机地址。

## 腕端固件与连接

`firmware/wearable` 现为 USB 专用固件，不启动无线发送。GPIO21/22 为 MPU6050 的 SDA/SCL，地址与 WHO_AM_I 均为 0x68；GPIO25/26 为低电平按钮 A/B。

```powershell
.\tools\build-local.ps1 -Action Build -Sketch wearable -ArduinoData C:\Users\21211\AppData\Local\Arduino15
# 确认设备身份、关闭串口监视器和网页连接后，才使用实际端口上传：
.\tools\build-local.ps1 -Action Upload -Sketch wearable -Port COM3 -ArduinoData C:\Users\21211\AppData\Local\Arduino15
```

COM3 只是当前腕端端口，插拔后重新枚举。网页选择 CH340 端口并连接；后端只读取串口，不发送握手或运动命令。收到合法腕端帧后才能显示已识别。若 Arduino 串口监视器占用端口，先关闭它。

固件 100Hz 采样，静置约 2.5 秒完成 250 样本校准；115200 波特率以 25Hz 输出不超过 384 字节的 USB NDJSON。字段为 `v,role,boot,seq,ms,age_ms,who,valid,cal,roll,pitch,a,b,mode,short,long,norm_g,temp_c,errors`。`short/long` 为累计事件计数，重连时不会补执行历史事件。

相对角度跟随版本增加 `att:2`：三轴陀螺共同参与四元数姿态更新，使用可信重力方向纠正倾斜；`roll/pitch` 表示相对开机参考的旋转向量 X/Y 分量，不再用独立 X/Y 角速度累加近似大角度姿态。静置时可刷新重力模长参考，但原始模长不缩放。MPU6050 没有磁力计，航向仍有漂移，也不提供手部平移位置；这不是完整六自由度位置跟踪。

## 实时操作

1. 放稳腕端、松开两个按钮，等待 IMU 有效。保持舒适的启用手势稳定约 0.5 秒。
2. 点击唯一的 **启用并回初始**。此时采集当前 IMU 参考，并将虚拟目标恢复为底座 0°、大小臂各 45°、夹爪打开。初始化完成后仍处于暂停，等待 A 短按。
3. **A 短按一次开始，再短按一次暂停**。松开 A 不会暂停，按住 A 也不会重复触发；参考只在网页启用时采集，不在每次 A 按下时重新设置。暂停后手腕可以移动，继续时按限速平滑追随当前手势对应的目标。
4. **B 短按只切换虚拟夹爪开合**。A 暂停期间也可操作 B，夹爪保持切换后的状态；没有大小臂模式或 B 长按模式切换。
5. Roll 控制底座。Pitch 控制大小臂 **同向协调** 抬起／放下，两关节从 45° 一起增加或减少；起点附近保留 5° 软死区，之后默认按 1° 对应 1°。固定倾斜后模型到目标停稳，输出仍受速度与加速度限制。
6. 暂停 A、软件停止、IMU 失效或数据过期时，转轴保持并清除追赶目标。虚拟夹爪不因暂停自动打开；重新点击网页“启用并回初始”时才恢复打开。断线或失效后不会自动恢复跟随，需要重新启用。

如果佩戴方向相反，在停止状态修改 Roll/Pitch 方向。仿真参数独立保存在 `data/virtual-config.json`，环境变量 `MOTIONARM_VIRTUAL_CONFIG` 可指定路径。不能把该配置作为实体安全行程标定。

原始姿态、启用时参考和修正角分别显示。比如原始 Roll 为 131°，可直接在这个舒适手势点击启用作为初始参考，无需勉强把手摆回传感器开机姿态。A 只是开始／暂停开关，不改变该参考。页面分别显示物理按钮是否按下，以及跟随当前是运行还是暂停。

**限位采用严格固定参考。** 大小臂使用共同的目标偏移和可行范围；任何一个关节触限时，两关节共同截住，避免失去配合。映射参考不会因越界或 A 暂停而平移；回到启用手势就对应初始姿态。手势超出范围后，需要退回有效角区，模型才继续移动，这与程序锁死不同。大小臂模拟输出采用两轴中较低的速度／加速度限制，保持协调。所有限位都是仿真参数，不代表实体机械臂安全行程。

如果显示“校准 0/250”，先松开 A/B 并静置约 3 秒；按着按钮或持续移动会使开机静置校准无法完成。腕端重启后需要等待重新校准，并重新确认中立手势。收到姿态／按钮遥测不等于运动已使能。

## 仿真与模型约定

默认底座 ±45°、大小臂向下角各 0–60°；速度 20/15/15°/s，加速度 60°/s²。启动目标为底座 0°、大小臂各 45°、夹爪打开；它不是竖直装配参考。

模型使用 `config/robot_baseline.json`：底板宽 90mm、肩轴高 90mm、肩肘轴距 115mm、肘至夹爪安装面 65mm、安装面至爪尖 90mm。Z 向上，+X 为底座前方。姿态字段是 `base_yaw_deg`、`shoulder_down_deg`、`elbow_down_deg` 和独立的 `gripper_open_ratio`（1 打开，0 闭合）。大臂仰角为 90°−α，小臂相对角为 −β。

竖直参考末端约 (0,0,360)mm；45°启动目标末端约 (236.3,0,171.3)mm。末端位置由简化正运动学估算，未包含装配偏移或实体位置闭环。

## 录制与历史回放

启用真实 IMU 控制后可开始录制；A 暂停时继续保存保持状态。每秒约 25 个样本，包含按钮、姿态、请求与输出目标、来源、几何及仿真配置快照。最长 10 分钟。数据无效、断线或重启时中断归档，保留原因。

进入历史模式先停止实时控制。可拖动时间轴预览，或对完整记录进行 1 倍速虚拟回放；不要求 IMU 在线。后端回放取得独立 REPLAY 控制权，期间实时输入不会改变轨迹，结束后需要重新启用实时控制。历史使用录制的几何参数。

中断记录可查看、导出，但不允许连续回放；缺口不生成插值动作。旧记录保留原来源与样本，角度约定不明确时仅查看和导出。CSV/JSON 中的目标不是实体实测值或实机验收结果。

## 接口与验证

`/api/status` 和 `/ws/telemetry` 使用 `schema_version=2`，分别携带 `input`、`imu`、`buttons`、`executor`、`control`、`joint_state`、`recording`、`replay`。执行端为 virtual，`joint_state.measured=null`。未来硬件遥测通过适配器转换到同一姿态约定，不能直接填入未知含义的舵机角。

- `GET /api/input/ports`；`POST /api/input/connect {port}`、`/disconnect`。
- `GET/POST /api/virtual/config`；`POST /api/virtual/enable` 与 `/prepare` 是同一个“稳定采样启用并回初始”动作；另有 `/stop`、`/reset`。页面仅保留一个初始化入口，不在 A 点击时改参考。`/neutral` 只是保留的停止状态接口，页面不再提供另一套参考设置流程。
- `GET /api/recordings`、`/{id}`、`/{id}/export?format=csv|json`；`POST /start {name}`、`/stop`。
- `POST /api/replays/preflight {record_id}`、`/start {preflight_id}`、`/stop`。

250ms 无新有效数据停止实时跟随；1 秒无合法协议帧进入断线重连；控制循环停顿超过 100ms 保持输出。数据新鲜度使用本机单调时钟，不跨设备直接相减时钟。

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-dev.txt
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m unittest discover -s backend\tests -v
cd frontend
npm run build
```

测试使用输入夹具，不构成产品模拟输入模式。真实双轴、按键和拔插需现场操作，自动测试不能代替。IMU 加速度模长存在随姿态变化偏离 1g 的已观测异常；界面保留原始值与提示，不乘系数掩盖，也不宣称传感器精度通过验收。

- 新增稳定手势中立准备、准确的门控状态及原因，修复离开死区后仍保留“已回中立”提示的问题。A 在两个控制周期之间短暂释放也会立即锁住运动，不能用新一次按下掩盖释放事件。
- 回归覆盖 131° 原始手势归零后，A 使能、底座／大小臂速度积分、B 夹爪与模式切换，以及移动／按键按住时拒绝设中立。后端 49 项、前端 11 项测试通过。

## 相对角度跟随修复（历史验证）

后续按用户选择切换为 `RELATIVE_ANGLE`，控制版本为 `relative-angle-v1`，并纳入配置标识及录制元数据。达到限位后继续向外转动，只调整跟随参考以丢弃越界量；不锁住控制权。测试覆盖三个轴上下限共六种情况：越界后反向 1°，请求目标立即退出限位，模拟输出按加速度限制开始退出。

固定 25° 手势在 5° 软死区下对应约 20° 目标变化，到达后停稳；不会像旧速度控制那样持续移动。松 A 后可以在任意手势重新按 A，重新捕获当前位置，不跳回起始姿态。配置保留旧满速角字段供历史兼容，当前角度跟随不使用该参数。

腕端升级为四元数 `att:2` 并已上传，开机校准、WHO_AM_I、25Hz USB 和原始诊断仍保留。纯 C++ 回归源码是 `firmware/tests/orientation_filter_test.cpp`，覆盖三轴复合旋转、120° 倾斜、1.58g 稳定输入、归一化和异常值。六轴估计仍没有绝对航向，也不提供平移位置。总相对转角经过 180° 时旋转向量有分支；若新姿态格式在 100ms 内出现超过 60° 的异常分量跳变，后端保持当前输出并重新接续，避免模型被分支跳变拉到另一侧限位。

## 当前按钮与协同控制

最新固件通过实际消抖按下边沿计数发送 `ac`、`bc`，A/B 按住不重复触发，释放不另算一次，开机已按住也不产生虚假点击。`mode` 兼容字段固定为 0；`short/long` 只保留诊断，不参与关节模式控制。USB 帧仍小于 384 字节。

陀螺仪量程已提高为 ±2000°/s（16.4 counts/(°/s)），原始读数接近 ±32700 时仍判定饱和。`gr` 报告量程，`rej` 为本次失效原因（1 总线读取、2 采样间隔、3 加速度失效、4 陀螺饱和、5 解算失效），`rc` 为拒绝计数，包含静置校准重试。恢复后的停控原因会保留，避免把“数据恢复有效”误当成“已经恢复跟随”。

后端使用 `COORDINATED_RELATIVE_ANGLE`，控制版本 `coordinated-angle-v1`，记录固定启用参考、按钮语义和 1:1 协同权重。初始化需要稳定真实输入以及新版 `ac/bc` 字段；回放或正在跟随时不允许重新初始化，暂停后可显式重新启用并回初始。

按钮主机回归可与姿态回归一样编译运行：`g++ -std=c++17 firmware/tests/button_input_test.cpp -o artifacts/button_input_test.exe`，然后执行生成程序。

新版现场验证：60 秒只读观测取得 1331 个状态快照，其中 566 个处于实际跟随状态；输入标识为 `relative_rotation_vector_v2`，控制标识为 `RELATIVE_ANGLE`。真实底座输出覆盖约 −33.6°～20.4°，小臂输出覆盖约 7.8°～60°，并观测到 **A 保持按下时从小臂 60° 上限反向退出**。该窗口为小臂模式，大臂保持 45°；不把未选中轴保持误判为映射失效。
