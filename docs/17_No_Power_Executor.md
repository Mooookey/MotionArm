# ESP-NOW 执行端第一阶段：无动力接入

本文保留第一阶段操作与2026-11-19实测证据，以下永久锁边界适用于 `robot_no_power` 构建。新增有动力空载流程见 [第二阶段](18_Powered_Empty_Trial.md)，不能将其权限用于解除无动力构建的锁。

本阶段只给 ESP32 和 PCA9685 逻辑侧供电，**舵机动力电源保持关闭**。当前 robot 固件没有 PWM 解锁或有效舵机脉冲输出实现。无动力测试通过不授权接通动力，不代表方向、行程、力矩、到位或带载抓放验收。

## 链路和执行端

MPU6050 → wearable → ESP-NOW v2（信道6、25Hz）→ robot 本地参考/控制/保护 → 软件目标 → 锁定的 PCA9685 输出层。USB 用于诊断、管理和 Web 遥测，不转发实时运动目标。腕端 USB v1/att:3 仍保持原字段和25Hz输出，拥塞时整帧丢弃不阻断无线。

- `virtual`：腕端 USB 是输入，Python 是虚拟执行端；虚拟请求和目标不表示实体接纳。
- `robot_no_power`：robot USB 遥测是实体端软件状态的唯一来源，腕端 USB 可独立作诊断。`requested` 是 robot 请求，`output_target` 是 robot 约束后的软件目标；PCA 输出仍锁定。
- `robot_powered`：本轮不可用，无解锁入口。没有外部轴角传感器，所有模式 `measured=null`。

切换执行端前必须停止控制、录制与回放。选择、连接、页面刷新、后端重启、无线恢复均不初始化、不获取控制权。端口号不表示板卡身份：腕端 STA MAC `EC:E3:34:EF:81:64`，robot `C0:CD:D6:D0:9B:54`；烧录前重新核对。

## 初始化与按钮

固定芯片正面向下，X向右、Y从手背指向手肘、Z向下。相对姿态为 `inverse(q_reference) ⊗ q_current`，Hamilton `[w,x,y,z]`。手腕旋转向量取 `[w,-y,x,z]` 的 SO(3) 对数，Roll控制底座，Pitch以1:1控制双臂；底座符号+1、双臂−1。

robot自己检查稳定窗口≥480ms、相邻样本≤100ms、三轴角速度模长<5°/s、窗口内最大三维姿态距离≤3°及按钮释放。显式初始化采集本次参考，请求0°/45°/45°和打开，保持暂停。该动作只初始化软件目标，不确认实物初态。

A消抖按下计数切换开始/暂停，按住和释放均不重复触发；B只切换夹爪，无mode。参考不在暂停、触限、按钮点击时改变。固定参考硬限位、大角度≥175°与跨180°保护、回到≤90°解除保护以及限速/加速度保持。无动力只读默认为死区5°、底座±45°、双臂0–60°、速度20/15/15°/s、加速度60°/s²，全部是软件联调参数。

## 独立夹爪保护

`OPEN_READY → CLOSING/CLOSED → OPENING → OPEN_READY`。首次有效闭合请求开始不可续期5000ms期限，包含闭合推进；提前点击B或到期均请求打开。A暂停、重复目标、重发帧、控制权变化均不续期。

打开推进不依赖姿态跟随启用状态。打开途中消费并忽略闭合点击；达到软件打开目标后，需要新鲜B释放状态，再允许新点击开始下一周期。累计多个B点击不能重建时序时强制打开并记录，不按奇偶翻转重新闭合。STOP、输入失效和断链更早释放，三条姿态轴保持最后软件目标。

5000ms是软件期限，**不是舵机堵转或温升安全认证**。正常有动力阶段应仅请求开爪，不能通过关闭全部PWM松爪，避免承重关节下垂。本阶段FULL_OFF仅是永久输出锁。

## 输出锁、故障和管理会话

启动将PCA全部通道设FULL_OFF，并回读CH12–15及配置寄存器，500ms周期健康检查。异常锁存故障、停止、清参考、请求打开；恢复通信只恢复可检查状态，仍需人工重新初始化。PCA读写成功不等于舵机动作或实测位置。

浏览器每250ms发送管理心跳，750ms失效；后端只为当前有效操作会话每100ms发送robot管理心跳；robot本地300ms超时自行停止并请求打开。关闭管理WebSocket立即尝试STOP，超时机制提供兜底。输入无效或有效年龄达到250ms也本地停止。计时使用单调时钟和无符号回绕计算，不依赖浏览器或FastAPI执行夹爪保护。

## 标定、记录和历史

`ArmProfile.h`保持空，`allow_arm/verified_on_hardware/operator_confirmed_initial_pose`保持false。配置schema2增加每轴`startup_deg`；`home_deg/home_us`继续表示映射锚点，不能将1630/1570竖直锚点替换为1030/1050的约45°启动脉宽。未知标定字段仍未知，启动值不构成实机确认。生成器仍要求完整实测及工位条件，当前配置必须拒绝生成。

新Web与录制schema4记录执行模式、双机boot、配置、参考、软件请求/目标、保护计时和事件。通信中断只记录最终已知状态与中断，不伪造打开完成。旧schema2/3保持原payload；明确角度语义的目标仅在虚拟查看器回放，不重新计算旧IMU，不套用新保护重写历史。旧演示和旧协议位于archive目录，不属于当前操作入口。

## 构建、烧录和无动力检查

使用英文路径和已安装ESP32 Core3.3.12：

```powershell
.\tools\build-local.ps1 -Action Build -Sketch wearable -ArduinoData C:\Users\21211\AppData\Local\Arduino15
.\tools\build-local.ps1 -Action Build -Sketch robot -ArduinoData C:\Users\21211\AppData\Local\Arduino15
```

构建不操作串口。烧录时由同一个操作者独占串口，先停止和释放后端串口，核对实际板卡MAC，复用对应构建目录的产物上传。不要为检查身份运行旧演示，不接通动力。

无动力检查依次确认身份/boot、信道和无线数据、WHO_AM_I/校准、新鲜度、PCA锁定回读、稳定初始化、A/B、软件限位和5秒自动打开；再检查无线失联、USB拔插、页面关闭和重启。结束必须STOP、打开软件目标、owner=NONE、参考清空、PWM锁定。无法无人值守制造的按钮/佩戴/物理拔插场景应明确记为待测，不能用夹具或串口ACK冒充实测。

现场结果与本次构建/测试结果见本文件后续验收记录；未写“通过”的项目保持待测。
