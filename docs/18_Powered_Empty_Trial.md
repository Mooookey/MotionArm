# 实体执行端：小范围空载联调

本阶段复用提交 `ad5644f` 与 [机械基线](Robot_Baseline.md) 的标定依据，接入正式 robot 本地 PWM 输出。实时输入仍为 MPU6050 → wearable → ESP-NOW v2 → robot；USB 仅用于管理、遥测与有界单轴诊断。禁止实体回放及带载抓放。

## 现场条件与范围

用户确认独立舵机电源额定 **5V / 6A**，可以人工直接切断动力。这是现场提供的额定信息，不是仪器测得的电压、电流、温升或承载验收。逻辑电源与舵机 V+ 分开、共地；PCA9685 通道为夹爪12、小臂13、底座14、大臂15。

正常通电且承重轴 PWM 保持时不要求持续托扶。**首次使能、计划断电或释放承重轴 PWM 前，先提醒并等待人员确认托住机械臂。** 首次使能前还须人工对齐 0°/45°/45°、夹爪打开。没有位置传感器，首次提交 PWM 无法从未知实物位置保证平滑过渡。

2026-11-26用户当前明确批准的实体观察范围：底座 **−45～+45°**，大臂和小臂 **20～60°**。此前±20°/35～55°的15/30观察后，用户明确反馈速度和加速度可以，要求再扩大范围并将实体底座方向取反。当前三轴速度上限 **15°/s**、加速度参数 **30°/s²**；夹爪开度变化仍为1/s，5°死区、启动0/45/45/open保持。它们不是机械安全极限，也不是扩大范围已经通过现场检查的声明。

本轮保留侧倾（Roll）控制底座，不改为手掌水平左右转向。传感器安装、Roll=−sensorY、Pitch=+sensorX及完整相对四元数不变；按本次用户对实物方向的明确反馈，只将实体底座关节符号+1改为−1，双臂仍−1。实体profile标记`coordinated-angle-v4`，虚拟/无动力旧v3及历史记录不改。已发现轨迹在限位终点直接清零速度的边界缺陷，原算法本轮保留，不能宣称软件速度状态全程严格满足加速度参数，更不能将其当作实体加速度测量。

## 标定与输出语义

映射采样点、启动姿态和允许运行范围分别保存，映射零点不要求位于本次20～60°范围内。底座−45/0/+45°对应1010/1610/2000名义µs，保持非对称分段映射；大臂0/45°对应1630/1030，小臂0/45°对应1570/1050。830/877约60°仍为外推说明。启动脉宽1610/1030/1050/1130，不覆盖竖直映射锚点。

沿用历史50Hz配置、prescale121、名义4.88µs计数基准；并未声称振荡器周期已测量。夹爪以开度比例1为打开1130、0为空载闭合1630，不虚构夹爪轴角。配置哈希绑定本次来源和限制；完整工作区、负载和热安全仍未验证。旧正式 `ArmProfile.h` 和未验收配置不因小范围试验被标为完整验收。

`requested` 是控制器请求；PWM保持时，`output_target` 是最近成功提交的受约束软件目标。输出未知或已禁能时，当前 `output_target` 为null，`last_committed_target`仅保存历史成功提交值。PWM计数和I²C写入成功不是位置反馈，禁能后保留的计数也只是历史值。`measured` 始终为 null。写入失败时停止推进并等待人工处置，不自动恢复输出、不声称已经保持或打开。

## 操作顺序

1. 舵机动力关闭，连接逻辑电源，按 MAC 核对板卡，确认固件模式、配置哈希、PCA寄存器与 FULL_OFF。无动力构建永久锁定，有动力构建也从 FULL_OFF 启动。
2. 在 Web 明确选择有动力执行端，执行准备。连接、握手、刷新和重启都不授权。
3. 提醒人员托住、人工对齐启动姿态；获得现场明确确认后再接通5V动力。独立执行使能PWM，保持暂停，观察是否正确保持。串口ACK只表示请求接纳。
4. 常规逐轴验收入口仍提供底座±5、±10、±15°、大小臂相对45°的±5、±10°，每次回启动位并等待现场反馈。用户本轮明确省去剩余分档，改用独立“直接初始化并观察”：必须绑定当前boot/配置/管理会话，输出已保持、无线稳定、无录制回放冲突，且仍通过robot稳定参考检查；只省去人工逐轴验收门槛。该授权作为观察事件和新记录元数据保存，不能将未测轴标成通过，STOP/失效/重连后不得自动恢复。扩大到±45°跟随限位不扩大诊断目标集合。
5. 佩戴方向保持芯片正面向下，X右、Y向手肘、Z下。释放A/B并静置，显式初始化采集稳定参考；已有输出回启动位必须限速推进，不能重置软件角度跳变。A点击开始/暂停，B点击夹爪。本轮不再分档，A开始后直接侧倾和抬压腕观察，最后A暂停；先不按B。对纯控制轴姿态，5°死区后1:1映射，需约50°侧倾才请求底座45°限位；不要求必须到极限，也不把请求到限位当作实物到位。
6. STOP清参考与控制权、冻结承重轴最后成功软件目标，并独立请求开爪。等待最新状态，不能把“已请求打开”写成“实物已打开”。
7. 提醒并等待托住确认，才释放PWM并人工断电。PCA故障时由现场托住后处置动力，不能靠Web虚假确认安全。

固定参考四元数、底座+1/双臂−1、Pitch双臂1:1、5°死区、175°及跨分支保护和≤90°恢复保持不变。暂停不重采参考。STOP、输入失效、无线250ms超时、管理300ms超时均清参考，恢复后不得自动继续。

夹爪首次闭合起最多5000ms，包含闭合推进。暂停、重发、重复帧及控制权变化不续期；提前B或故障更早请求打开。打开过程忽略闭合事件；到软件打开目标并收到新鲜B释放后才允许新周期。不得通过关闭全部PWM松爪。

## 遥测、记录与兼容

无线82字节v2与腕端 USB att:3/115200保持原义。有动力 robot 使用独立USB协议v3、230400，完整快照5Hz、每行≤512字节；无动力robot USB v2/115200保留。客户端严格匹配模式、版本、身份与配置，不回退接管。

Web及新录制schema5区分虚拟目标、无动力软件目标和实体最近提交软件目标，保存配置、双机boot、PWM阶段、保护事件和人工观察记录。动力状态只按人员确认标注，不冒充电压传感器。schema2/3/4原记录保持不变；明确目标语义的历史仅按保存目标在虚拟执行端回放，实体需停止并断开运动管理，绝不下发实体回放目标。
