# 基于 ESP32 的六轴 IMU 数据采集、滤波与性能评测

## 摘要与主要结论

本实验完成了从 MPU6050 六轴采样、ESP32 端校准与处理，到电脑 Web 上位机显示、保存和评测的完整系统。ESP32 以200Hz采集，在设备端记录采样时间，输出原始六轴、处理后六轴、四元数和三轴位移；电脑端显示对比曲线、欧拉角及带XYZ标签的三维模型，并保存CSV和完整记录。

305秒记录共生成61000帧，电脑有效去重接收61000帧，本次丢包率为0%，CRC异常、采样失败、错过周期及队列丢弃均为0。设备统计实际采样频率200Hz，间隔均值5000µs、标准差2.6444µs。前60秒处理后三轴陀螺标准差分别降低20.988%、19.606%、25.671%；前300秒陀螺独立积分的累计角度由原始的[−1657.065049,277.300227,−30.952867]°降至[−3.110696,3.898886,1.465728]°。

这些结果说明本次采集与传输稳定，启动扣偏和低通降低了均值残差与数据波动。第二轮动态展示段中，主要动作变化仍得到保留，但出现幅值减小；陀螺辅助相关峰约落后一个5ms采样周期。与此同时，近似水平放置不能提供严格加速度参考，单姿态重力模长归一不能证明三轴标定准确，六轴偏航仍会漂移。位移实物尝试保留了明显的积分误差，不能认定为准确定位。报告分别讨论“功能运行”“数据完整”和“测量准确”，不将其中一项通过视为全部通过。

## 1 实验目标与实现结构

### 1.1 实验目标

本实验的目标是用统一硬件建立可复现的数据链路，并用实际记录说明数据是否稳定、传输是否完整，以及处理前后的变化。我将采集、处理和显示分开设计：时间基准与算法放在ESP32，电脑负责展示、完整保存和离线复算。这样可避免把浏览器接收抖动误认为传感器采样抖动，也能保留原始数据检查处理是否掩盖问题。

### 1.2 硬件与连接

开发板为ESP32-D0WDQ6，Arduino板型ESP32 Dev Module；传感器为野火小智MPU6050模块，I²C地址0x68。传感器由3.3V供电，使用现有四线连接，没有增加OLED或其他传感器。

| MPU6050引脚 | ESP32连接 | 说明 |
|---|---|---|
| VCC | 3V3 | 3.3V供电 |
| GND | GND | 公共地 |
| SDA | GPIO21 | I²C数据 |
| SCL | GPIO22 | I²C时钟，100kHz |

软件保持已安装的ESP32核心3.3.12和现有库版本。上位机使用本地网页、Web Serial和原生Canvas，不依赖网络下载图表库。上传速率为115200，正式数据通信速率为460800、8N1；上传设置与运行设置独立。

### 1.3 六项基本任务的实现

| 基本任务 | 本实验的实现方式 | 对应证据 |
|---|---|---|
| 稳定读取六轴 | 5ms定时通知采样任务，检查I²C读取及新样本标志 | 原始数据、设备时间戳、间隔统计 |
| 校准和滤波 | 启动陀螺扣偏、单姿态模长比例、一阶低通、Mahony及位移积分 | 参数摘要、前后对比、姿态与位移记录 |
| 传输、显示和保存 | 逐采样二进制帧、本地Web曲线与模型、CSV/JSON导出 | 完整源代码、截图、数据文件 |
| 检查完整性 | 会话号、序号、CRC、设备生成计数及独立错误计数 | 结束摘要、丢包及异常统计 |
| 统一测试与分析 | 305秒记录覆盖60秒统计和300秒积分，另录动态动作 | 六项定量指标及计算 |
| 三维姿态及轴对齐 | 带XYZ标签模型、三个方向动作与复位、连续展示 | 动作切片、观察记录及独立视频附件 |

MPU6050内部输出设置为1kHz，ESP32每5ms读取最新样本，最终采集与发帧频率为200Hz。定时器只通知任务，不在中断中执行I²C或串口发送。采样任务完成读数、处理和帧生成，发送任务通过有界队列输出；序号在入队前分配，队列满导致的丢帧仍能被接收端识别。

采样采用可检查返回码和长度的连续读取，同时读取DATA_RDY状态。读取失败或没有新样本时增加独立计数，不用旧样本伪装新数据。ESP32的64位微秒时间戳记录实际读取开始时间；滤波和积分均使用相邻设备时间的真实间隔。

## 2 参数、单位与ESP32端算法

### 2.1 参数与数据定义

原始加速度按固定量程换算为m/s²，角速度为°/s。raw表示芯片寄存器数据经单位换算后的结果，尚未进行软件扣偏、比例修正或低通；它已经受芯片内部DLPF影响。因此本实验比较的是共同硬件滤波之后，额外软件处理带来的变化。

| 参数 | 设置或本次静态记录值 |
|---|---|
| ESP32采样 | 200Hz，名义周期5000µs |
| MPU6050内部输出 | 1000Hz |
| 加速度量程/换算 | ±4g，8192LSB/g，g=9.80665m/s² |
| 陀螺量程/换算 | ±500°/s，65.5LSB/(°/s) |
| 硬件DLPF/软件低通 | 44Hz/20Hz |
| 静态记录陀螺零偏XYZ | [−5.51317501,0.91133881,−0.10806219]°/s |
| 静态记录加速度比例κ | 0.869825006 |
| 静态记录独立校准样本数 | 602 |
| Mahony参数 | Kp=0.5，Ki=0 |
| 四元数约定 | [w,x,y,z]，传感器body→world |
| 坐标与欧拉角 | 右手系、世界Z向上；ZYX顺序 |

### 2.2 启动校准及其限制

启动后先采集约3秒稳定数据，以三轴角速度均值作为零偏b，随后使用ω′=ω_raw−b。校准以样本稳定性为主，加速度模长只以0.5g～1.5g作合理性筛查，避免把模长偏离g但稳定的样本一概当作运动。校准完成后另开测试会话，测试期间固定校准值，不用评测数据重新估计零偏。

加速度另外采用单姿态模长比例κ=g/‖mean(a_raw)‖，处理链为κ·a_raw再低通，参数与方法single_pose_norm_scale写入记录。raw完整保留，不应用κ。此方法只调整整体重力模长，不能分别辨识各轴偏置、各轴增益、轴间误差与放置倾斜，也不能替代六面标定。处理后同姿态模长接近g，是归一化的预期效果，不是独立的精度证明。

### 2.3 一阶低通

六轴采用相同截止频率的一阶低通：

`y[k] = y[k−1] + α·(x[k]−y[k−1])`

`α = 1−exp(−2π·fc·dt)`

其中fc=20Hz，dt由ESP32相邻采样时间戳计算；名义dt=0.005s时，α=1−exp(−2π×20×0.005)≈0.4665。首次有效样本初始化滤波器。陀螺的x为扣偏后的角速度，加速度的x为κ·raw。

我选择该滤波器，是因为计算量小、参数意义清楚，能在200Hz实时链路中直接比较平滑和响应的取舍。截止频率降低通常会增强平滑，同时增加变化被延迟或削弱的风险，所以不能只凭静态曲线更平滑判断方案更好。

### 2.4 姿态、重力剔除与位移

姿态采用六轴Mahony融合，以陀螺提供短时转动信息，用加速度的重力方向修正倾斜，更新后归一化四元数。内部角速度按实现转换为rad/s，输出角速度保留°/s，避免单位混用。初始化由重力确定Roll/Pitch，Yaw相对初始方向定义为0。没有磁力计，不能提供长期稳定的绝对航向。

模型使用ESP32输出四元数直接旋转，网页再计算欧拉角用于数值显示；不分别交换角度分量来修补模型方向。Pitch接近±90°时欧拉角存在奇异性，因此轴向判断结合物理方向、角速度和四元数模型。

世界系线加速度与位移链路为：

`a_world = R(q)·a_body − [0,0,g]`

`v[k] = v[k−1] + (a_world[k−1]+a_world[k])·dt/2`

`p[k] = p[k−1] + (v[k−1]+v[k])·dt/2`

静止零速约束将速度置零，位置只在明确归零时重置；超过20ms的异常积分间隔不桥接。零速约束依赖“起止静止”的动作假设，无法仅凭理想六轴信号可靠区分静止与匀速运动，也不能恢复已经积累的位置误差。

## 3 传输、保存与测试设计

### 3.1 帧结构与完整性

每次成功采样产生一个90字节数据帧，包括帧头、版本、类型、长度、会话ID、递增序号、64位采样时间戳、状态、原始六轴整数、处理六轴浮点、四元数、位移和CRC16/CCITT-FALSE。多字节字段采用小端。配置、状态和结束摘要使用独立消息类型，不与未封装调试文本混发。

200Hz时数据帧约18000B/s。460800、8N1的理论字节容量约46080B/s，数据帧占约39.1%，为状态消息与实际调度留出余量。该预算只说明容量可行，可靠性仍以真实记录中的CRC和计数验证。

START由设备确认新会话；STOP停止该次帧生成，排空队列后返回END。丢包率分母使用END.generated，接收端仅计算该会话CRC正确、有限数值且不重复的数据帧。失读、无新样本、错过周期与队列丢弃分别计数。没有END时，不能根据收到的首尾序号推断完整测试为零丢包。

网页以约30Hz绘制曲线和模型，接收与记录保留全部200Hz数据。保存文件包括CSV、完整JSON、参数与诊断摘要及图文件；记录可以导入网页回放。超过500ms没有有效新帧时给出断流提示；浏览器接收时间只用于该提示，不代替设备采样时间。

## 4 指标一：测量误差

水平且+Z向上时，加速度参考为[0,0,g]，角速度参考为[0,0,0]。在同一前60秒窗口计算均值，原始和处理后使用相同样本。

`角速度误差 = mean(ω_i)−0，单位°/s`

`加速度误差 = 1000·(mean(a_i)−a_ref_i)/g，单位mg`

| 加速度轴 | 原始均值m/s² | 处理均值m/s² | 原始参考差mg | 处理参考差mg |
|---|---|---|---|---|
| ax | 0.377994 | 0.328790 | 38.544698 | 33.527250 |
| ay | −4.098074 | −3.564604 | −417.887278 | −363.488496 |
| az | 10.497869 | 9.131311 | 70.484680 | −68.865398 |

| 陀螺轴 | 原始均值/误差°/s | 处理均值/误差°/s |
|---|---|---|
| gx | −5.521051 | −0.007877 |
| gy | 0.916019 | 0.004665 |
| gz | −0.104419 | 0.003640 |

代入原始ax：1000×0.3779943634/9.80665=38.544698mg。代入原始az：1000×(10.4978685888−9.80665)/9.80665=70.484680mg。陀螺gx扣偏前均值为−5.52105089°/s，减去独立校准值−5.51317501°/s，得到约−0.00787588°/s，与低通后均值−0.00787711°/s相符。

处理后陀螺均值残差明显减小。加速度方面，原始/处理均值向量模长约11.275741/9.807923m/s²，但Y分量仍很大；倾斜投影与器件误差不能在本次单姿态试验中分离。故不能将模长归一后的接近g，直接作为三轴准确性改善的证据。严格器件偏置比较还需要可靠水平参考与多姿态标定。

## 6 指标三：五分钟静止角度漂移

本项使用校准后的新会话，分别对原始角速度和处理后角速度独立积分，不使用融合后的欧拉角。每轴按真实相邻设备时间间隔采用梯形法：

`θ_i = Σ((ω_i[k−1]+ω_i[k])/2)·((t_us[k]−t_us[k−1])/10⁶)`

| 轴 | 原始累计角度° | 处理累计角度° | 实际积分时长 |
|---|---|---|---|
| X | −1657.065049 | −3.110696 | 300s |
| Y | 277.300227 | 3.898886 | 300s |
| Z | −30.952867 | 1.465728 | 300s |

本次没有缺样、时间倒序或超过20ms的积分间断，跳过区间数为0。X累计角度绝对值降低比例为(1−3.110695704/1657.065049336)×100%=99.812277%；Y、Z分别约98.593984%、95.264644%。图3显示三轴原始与处理累计角度随设备时间的变化。

原始X累计量很大，与约−5.5°/s的固定零偏长期积累相符；扣偏后下降明显。这主要体现零偏校准作用，不能全部归因于低通。处理后300秒仍残留约1.47～3.90°累计角度，说明一次启动校准不能消除全部漂移。本次没有独立角度基准，也保留近似静置条件限制，不能由此宣称长期绝对姿态精确。

## 7 指标四：数据丢包率与异常

丢包率采用同一完整会话的设备最终生成总数与接收去重有效总数：

`丢包率 = (N_generated−N_unique_valid)/N_generated×100%`

| 计数项 | 本次305秒记录 |
|---|---|
| 设备生成/发送帧数 | 61000/61000 |
| 电脑有效且不重复接收数 | 61000 |
| 丢帧数/丢包率 | 0/0% |
| 重复/倒序/CRC异常/异常帧 | 0/0/0/0 |
| 采样失败/无新样本 | 0/0 |
| 错过周期/队列丢弃/积分间断 | 0/0/0 |

代入计算：(61000−61000)/61000×100%=0%。头部与尾部缺失均为0，END摘要已经确认，因此不是只对“已收到的中间一段”计算零丢包。图4列出完整会话计数与序号缺失情况。

动态和位移切片保留原序号，但切片本身没有新的设备END；其end=null，source_end只提供完整源会话背景，不能作为切片生成总数来伪造零丢包。采样失败也独立于传输丢包统计。本次结果证明这305秒链路完整，不外推所有环境、所有时长均零丢包。

## 8 指标五：采样稳定性

本项优先采用ESP32对相邻成功采样间隔的统计，避免将电脑端接收缺帧误认为设备采样间隔变长。频率由实际时间计算：

`f_actual = 10⁶/mean(Δt_us)`

| 指标 | 设备端统计 |
|---|---|
| 间隔数 | 60999 |
| 实际频率 | 200.000000Hz |
| 间隔均值/标准差 | 5000.000µs/2.6444µs |
| 最小/最大间隔 | 4970µs/5030µs |
| 错过采样周期 | 0 |

实际频率=1000000/5000=200Hz。间隔标准差相对名义周期为2.6444/5000×100%=0.052888%；最大单次偏离为30µs，即30/5000×100%=0.6%。设备时序在本次记录中接近名义5ms。

图5为连续序号的相邻设备采样间隔。电脑端独立复算只使用序号连续且时间递增的相邻对，序号缺口单列。本次没有接收缺帧，因此设备统计与接收记录的时间关系一致；结论来自实际时间戳，而不是仅报告设定200Hz。

## 9 指标六：动态滤波响应

### 9.1 动作选择与数据完整保留

动态完整记录为73.815秒、14764帧。起始0～20秒已经在运动，且混杂早期操作；这些数据完整保留，但不作为规范轴向示例。我按第二轮动作顺序、主要角速度轴及起止行为选择区间，不因为早期某一段数值更好而改选。

| 示例动作 | 原会话时间 | 原会话序号 | 说明 |

## 10 指标七：三维姿态显示与轴对齐

上位机模型为带XYZ标签的长方体，模型局部轴对应传感器丝印轴，显示视角转换统一处理。验证先确认水平初始姿态，再依次绕物理+X、+Y、+Z按右手方向转动，每项结束回初始姿态；数值欧拉角与四元数同时保留。

| 步骤 | 验证动作 | 判断内容 |
|---|---|---|
| 1 | 初始姿态，+Z朝上 | 模型姿态及XYZ标签与实体对应 |
| 2 | 绕+X正向抬转后复位 | X轴转向及gx主要符号一致 |
| 3 | 绕+Y正向抬转后复位 | Y主导动作方向一致，保留混轴事实 |
| 4 | 俯视绕+Z逆时针转动后复位 | Z轴转向及gz主要符号一致 |

操作中三个方向的实体与模型同步及复位情况得到确认，数据提供对应角速度和四元数作为辅助。43.75秒连续展示段包含X/Y/Z、停顿和组合动作；它证明记录连续覆盖该时长，不能仅凭长度就宣称全过程超过30秒都在不间断转动。实际连续转动跟随应以影像内容核验。

轴向验证录像录制于独立设备。当前工程未包含视频原件，第七项影像证据须以归档后的原件验收，不能用曲线、操作确认或相关分析代替。传感器数据本身也不能自动证明外部物理方向。六轴Yaw只相对于初始方向，短时同向跟随不等于绝对航向精度。

## 11 位移实物尝试与失败边界

位移完整会话长22.58秒、4517帧，生成数等于有效去重接收数，CRC为0。动作按约15cm往返进行，没有独立尺量的距离基准，因此不据此给出正式百分比定位精度。

为减少早期混杂影响，选取6.325～10.070秒、seq1265～2014的起止静止尝试，共750帧、3.745秒。起始6.325～6.675秒与末尾9.865～10.070秒的静止标志均为100%，该段最大四元数变化约3.91°。这些条件只说明记录中算法判静止及姿态变化相对较小，不证明世界系线加速度或速度准确。

| 位移量 | 实际记录 |
|---|---|
| 选段起点位置m | [0.072739,−0.143142,0.500777] |
| 选段终点位置m | [0.150670,−0.059322,1.068854] |
| 选段位置增量m | [0.077931,0.083819,0.568077] |
| 选段增量模长 | 0.579491m |
| 全会话末位置m | [0.969496,1.741560,2.880592] |
| 全会话首末净变化模长 | 3.502017m |

选段增量模长由sqrt(0.07793055²+0.08381941²+0.56807673²)≈0.579491m计算。其Z增量占主要部分，与短距离往返动作不相称；全段还存在更大的净漂移。因此只能认定“位移计算和显示已运行”，不能认定“15cm往返定位准确达标”。

误差不能全部归结为操作。运动期间姿态误差会造成重力泄漏，单姿态比例无法校正全部加速度偏置，残余加速度经二次积分会放大。作为敏感度示例，若有1°倾斜估计误差，g·sin1°约0.171m/s²；不受约束地积累4秒可造成约0.5×0.171×4²=1.37m位置误差。这只是机制示例，不是本次实测姿态误差。ZUPT将静止速度置零，也不能消除之前已积累的位置偏差。本次保留失败数据，作为后续算法改进的边界证据。

## 12 方案取舍、可复现性与仍存问题

本实验选择有线本地Web，是为了复用已经验证的USB链路，在离线条件下减少额外依赖；运行通信速率提高到460800后，通过完整会话计数验证本次可靠性。选择简单低通而不引入复杂卡尔曼，是为了在限时训练中先得到可解释、可验证的处理链，而不是用复杂名称替代实验。

Mahony用于姿态，独立角速度积分用于漂移指标，两者不混用；原始数据、校准参数、处理数据同时保存，使结果可复算。数据切片保留原始序号、时间戳、源文件SHA256和选择理由，不删除原记录中的早期错误动作，也不根据接近预期结果来挑选。软件验证覆盖拆包粘包、CRC、缺失重复帧、单位与姿态坐标，以及短窗口不能冒充完整测试等情况。

仍存在的主要问题包括：人工水平参考不足、启动校准难以补偿全部温漂、单姿态加速度校准能力有限、动态线加速度会干扰重力方向、无磁力计导致偏航漂移，以及积分位移对残差极敏感。每项限制都能在现有硬件或数据中找到对应原因，不能靠静止时模型看起来平稳来忽略。

## 13 具体拓展：设备搬运倾倒与冲击事件记录器

在现有ESP32和MPU6050上，我希望进一步实现实验仪器或设备箱搬运过程的倾倒、异常翻转与碰撞事件记录。当前系统连续显示曲线，事后仍需人工寻找异常；拓展后的目标是直接回答“何时发生事件、持续多久、最大倾角或冲击量多大”，并保留事件前后数据供回放，而不是继续追求本次已证明不可靠的自由空间积分定位。

硬件仍使用同一开发板和IMU，将模块固定在设备箱上并记录安装轴向，USB供电与电脑接收即可构成第一版。软件新增四部分逻辑：第一，启动建立安装姿态参考；第二，以相对参考的倾角、角速度和加速度模长变化建立事件状态机；第三，环形缓存保存事件前后数据；第四，在网页生成事件列表、回放入口和确认标记。每项事件保存设备时间戳、类型、持续时间、峰值、参数版本及对应数据区间。

倾倒判据可从“相对倾角超过30°持续0.5秒”作为试验初值，并用较低恢复阈值避免状态反复切换；冲击判据从静态背景分布确定，例如模长变化超过背景均值加若干倍标准差，并结合最短持续时间和冷却时间抑制重复触发。这些数值只是下一阶段设计初值，不是已经验证的阈值。冲击支路可读取校准后的原始加速度，避免额外20Hz低通过度削弱短时峰值，同时保留芯片44Hz带宽和±4g量程的限制，遇接近量程的数据应标记削顶风险。

事件前后合计5秒、按90字节和200Hz保存约需90000字节。实现前先测量剩余内存，再选择紧凑缓存或及时向电脑落盘；不直接假定全部历史都能长期保存在ESP32内。没有网络或电脑时，可先保留少量事件摘要，后续再扩展事件取回功能。

验证设计分为阈值建立与独立测试两阶段。先采集正常放置、平稳搬运和日常轻微振动，用来建立背景；再用不同批次的正常搬运、缓慢倾倒、快速翻转和可控轻碰动作测试，至少逐类重复并保留外部视频标签。评价事件检出率、误报率、重复触发、时间定位偏差和缓存完整性；检测参数固定后再做验证，不用同一批数据同时调阈值和宣称性能。还应专门测试不同安装方向、供电重连和传感器读失败，检查是否将故障误报为冲击。

这一拓展与手上硬件能力更匹配：倾角和事件检测主要利用姿态及短时信号，不依赖长时间二次积分；新增状态机、缓存和事件解释后，系统能从“展示传感器数值”进一步解决具体搬运场景中的异常追溯问题。
